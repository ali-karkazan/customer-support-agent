# Project Reflection

I used the Knowledge Base search tool to ground the agent’s product and policy answers in the store’s supplied catalog. The model’s general knowledge may not match the policies of this particular store, so relying on it could give customers incorrect information. During testing, I saw the agent add unsupported loyalty benefits when retrieval failed. This showed me that providing a retrieval tool is not enough: the agent also needs clear instructions to use the retrieved evidence and avoid guessing when that evidence is unavailable.

After deploying the agent, I tested whether it could retrieve information from the Knowledge Base. The test initially failed. I added exception logging and inspected the CloudWatch logs, which showed that the deployed agent’s execution role lacked the `bedrock:Retrieve` permission. I resolved this in the AWS IAM console by granting the role access to the specific Knowledge Base, then repeated the test successfully. This taught me that successful local testing does not guarantee that a deployed agent has the permissions it needs.

For production use, I would improve refund processing to prevent duplicate requests. The mock refund function generates a new refund ID each time it is called, so repeated requests could create multiple refunds without the agent recognizing the duplication. I would store refund records in a database and make the backend check for an existing refund before creating another. Repeated requests should return the existing result instead of processing the refund again. This protection should be enforced by the backend rather than relying only on the agent’s instructions.
